Behind the scenes

How this site is built

I originally built this site to force myself to learn Kubernetes. That worked, but a cluster is a lot to run for a personal site. So I rebuilt the hosting around containers on Azure, using the services and practices I most want to know well. This page is honest about what is finished and what is still a plan.

Where it started

The first version was an ASP.NET Core application in a Docker container, deployed to a Kubernetes cluster with Helm charts and an Nginx ingress, and released through Azure DevOps pipelines. It taught me a great deal about how those pieces fit together.

It also showed me the cost. A small always-on cluster needs patching, monitoring, and money every month, and for a handful of web pages that's far more than the job needs. Kubernetes is a tool I'm still learning, and I'd rather say so than pretend otherwise.

Where it is now

A status board, so you can see what's real.

  • DoneA fresh, accessible front end.

    Plain HTML and CSS with no front-end framework and no build step. It's built with keyboard use, screen readers, and reduced-motion settings in mind, and it loads quickly.

  • DoneCurrent runtime and a container.

    ASP.NET Core 10 (upgraded from .NET Core 3.1) in a small multi-stage Docker image that runs as a non-root user.

  • DoneAzure Container Apps and Container Registry.

    The image is built in Azure Container Registry and runs on Container Apps with HTTPS and scale-to-zero, so it costs almost nothing when nobody is visiting. A budget alert watches the subscription.

  • DoneInfrastructure as code with Bicep.

    One template defines every Azure resource for both environments, with a small parameter file for each. The custom domain and its free managed certificate are in the same template.

  • DoneGitHub and a build-and-release pipeline.

    GitHub Actions builds the image once, deploys it to dev automatically, then waits for my approval before promoting the same image to prod. Pull requests are required for main, and Dependabot keeps dependencies current.

  • DoneNo stored passwords.

    The pipeline signs in to Azure with short-lived OIDC tokens, and the app pulls its image with a managed identity that can only read from the registry.

  • NextMonitoring.

    Application Insights with a KQL dashboard for availability, errors, and performance. Logs already flow to Log Analytics.

  • LaterKey Vault.

    Only if the site ever needs a secret. Today there are none to store.

  • LaterA real contact form.

    The old form depended on PHP, which doesn't run here. The replacement would be an Azure Function that queues messages through Service Bus and emails me.

  • LaterAn "Ask Glenn" assistant.

    A chat box that answers questions about my experience using vector search over my resume and project write-ups, with Redis for caching and rate limits and a firm spending cap.

The architecture

Solid outlines are deployed; dashed outlines are planned.

Select the diagram to open it full size. The contact form and the assistant are separate add-ons, and the last pieces I plan to build. The assistant will only go live once spending limits are in place.

Why these choices

  • Container Apps instead of Kubernetes. It runs the same kind of container with a fraction of the operational work, and it can scale to zero. A site with a handful of visitors shouldn't pay for an idle cluster.
  • Bicep for everything. If it isn't in code, it can't be reviewed, repeated, or safely deleted.
  • Approval before prod. The same image that passed in dev is promoted, never rebuilt, and a human approves the step. It's the same habit I use at work.
  • Managed identity, not passwords. The fewer secrets there are, the fewer can leak.
  • Monitoring. You can't run what you can't see, so logs are collected already and a dashboard is next.

It's also my study project for Microsoft's AI-200 exam (Azure AI Cloud Developer): containers, data services, messaging, and security and monitoring are all on that list, and building something real is the best way I know to learn them.
